# 엘리베이터 이상현상 게임 기획서 (가제: 지상까지)

- 상태: 기획 v0.1 (구현 전)
- 장르: 1인칭 이상현상 찾기 공포 (8번 출구류)
- 차별점: 수평 이동(통로) 대신 수직 이동(엘리베이터). 좁은 밀실, 문이 닫히는 시간 압박, 층 표시판이 곧 진행도
- 기술: 기존 게임과 같은 단일 `index.html` + Three.js r128, 경로 `elevator/`

## 1. 확정된 결정 (사용자 선택)

| 항목 | 결정 |
|---|---|
| 판정 규칙 | 이상 없으면 ▲, 이상 있으면 ▼ |
| 이동 범위 | 엘리베이터 안만 (로비는 열린 문으로만 보임) |
| 시간 압박 | 시작 화면에서 난이도로 선택 (느긋하게 / 보통) |
| 공포 수위 | 원작 수준 + 추락 연출, 갑자기 놀래키는 장면은 1~2종 |

## 2. 핵심 루프

```
[탑승 운행] → [도착, 문 열림] → [관찰] → [▲ 또는 ▼ 누름] → [문 닫힘] → 다음 루프의 [탑승 운행]
```

- 한 루프 = "이번 운행 + 이번에 도착한 층". 판정 대상은 문이 닫힌 직후부터 버튼을 누르기 전까지 본 모든 것
  - 운행 중(문 닫힘 상태)에도 이상현상이 나올 수 있음. 엘리베이터만의 요소
- 시작: B8. 목표: 1F(지상)
- 정답: 층 표시가 한 층 오름 (B8 → B7 → … → B1 → 1F)
- 오답: 조명이 꺼지고 케이블 끊기는 소리와 함께 B8까지 추락, 처음부터
- 1F 도착: 문 너머로 햇빛이 드는 로비, 내리면 엔딩

### 2.1 ▼를 눌렀는데 위층에 도착하는 모순

- ▼(정답)를 누르면 몸으로 느끼는 운행 방향은 아래(화면 흔들림, 모터 소리, 화살표 ▼)인데, 도착하면 층 표시는 한 층 위
- 원작에서 "되돌아갔는데 번호가 오르는" 추상화와 같은 구조. 여기서는 그 어긋남을 숨기지 않고 "이 건물은 층이 맞지 않는다"는 분위기로 이용
- 혼란 방지: 엘리베이터 안 안내문에 규칙을 명시

```
승강기 이용 안내
· 이상이 없으면 ▲ 를 누르십시오.
· 이상이 있으면 ▼ 를 누르십시오.
· 지상(1F)에 도착하면 내리십시오.
```

## 3. 시간 압박 (난이도 선택)

| 모드 | 문 열림 유지 | 시간 초과 시 |
|---|---|---|
| 느긋하게 | 무제한 | 없음 |
| 보통 | 12초, 남은 3초부터 경고음 | 문이 닫히고 오답 처리(추락) |

- 보통 모드의 열림 버튼: 누를 때마다 +4초, 한 층에서 최대 2회
- 닫힘 버튼: "고장" 스티커가 붙어 있고 눌러도 반응 없음. 시간 초과 외에 버튼 없이 진행하는 방법을 막는 장치이자 소품
- 문이 열리는 동작은 약 1.2초. 타이머는 문이 다 열린 순간부터 셈

## 4. 공간 설계

### 4.1 엘리베이터 안 (약 2.0 × 1.8 × 2.4m)

| 위치 | 기준 소품 | 비고 |
|---|---|---|
| 정면 | 양쪽으로 열리는 문, 문 위 층 표시판(화살표+층) | 플레이어 시작 시 정면 |
| 오른쪽 벽 | 버튼판(▲, ▼, 열림, 닫힘(고장), 비상 인터폰), 정원 표시 | 상호작용 대상 |
| 왼쪽 벽 | 광고 액자 1개, 승강기 안전검사 필증 | |
| 뒷벽 | 전면 거울, 허리 높이 손잡이 | 거울 이상현상의 무대 |
| 천장 | 사각 조명 패널, CCTV 돔 | |
| 바닥 | 매트 | |

### 4.2 로비 (문 너머로만 보임)

- 모든 층의 로비는 층 번호를 빼고 완전히 같음. 플레이어가 첫 운행에서 기준 모습을 외우는 구조
- 구성: 정면 벽의 층 표지(예: "B5"), 왼쪽 방화문, 오른쪽 화분, 벽등 2개, 소화전, 바닥 타일
- 관리인 NPC: 정해진 층(짝수 층)에서 청소 카트 옆에 서 있음. 8번 출구의 "걸어오는 남자" 역할

### 4.3 거울 구현 방식 (권장: 가짜 방)

- 반사 렌더링(Reflector) 대신, 뒷벽 너머에 엘리베이터 안을 좌우 반전으로 한 벌 더 만들어 놓고 벽을 투명 창처럼 처리
- 장점: 거울 속만 따로 바꿀 수 있음. 거울 이상현상(거울에만 있는 사람 등)이 곧 "복사본의 일부 수정"이 되어 구현이 쉬움
- 필요한 것: 플레이어 몸체 모델(거울에만 보임, 카메라 위치와 시점을 따라 움직임)
- 비용: 복사본 오브젝트 수가 2배. 공간이 좁아서 성능 부담은 작을 것으로 예상(추측)

### 5.5 이상현상 설계 원칙

- 한 루프에 이상현상은 최대 1개
- 플레이어가 서 있는 자리에서 관찰 시간 안에 볼 수 있어야 함 (보통 모드 12초 기준)
- 소리만으로 알 수 있는 이상현상은 반드시 시각 단서를 함께 둠 (예: 노크 소리 + 조명 흔들림)
  - 이유: 소리를 끈 플레이어에게 불공정. 선택 옵션으로 "[소리] 천장에서 두드리는 소리" 자막 제공 검토
- 같은 이상현상은 전체 목록을 한 바퀴 돌기 전에 다시 나오지 않음 (끝없는 통로와 같은 섞기 방식)

## 6. 확률과 난이도 곡선

- 첫 운행(B8 출발)은 항상 정상. 기준 모습을 보여 주는 튜토리얼 역할
- 이후 이상현상 등장 확률 p = 0.55 (초기값, 플레이테스트로 조정)
- 진행 층에 따라 어려운 이상현상 비중을 높임

```
진행도 k = 0(B8) … 7(B1)
P(어려움 | k) = 0.10 + 0.05·k        → B8에서 0.10, B1에서 0.45
P(쉬움 | k)   = 0.45 − 0.05·k        → B8에서 0.45, B1에서 0.10
P(보통 | k)   = 0.45
```

- 풀이: 낮은 층에서는 쉬운 이상현상으로 규칙을 익히고, 지상에 가까울수록 어려운 것이 나와 긴장이 오름. 세 확률의 합은 항상 1

### 6.1 예상 플레이 시간

- 루프 1회 정확도를 a라 하면, 8번 연속 정답이 나올 때까지 필요한 루프 수의 기댓값

```
E[루프 수] = (1 − a⁸) / ((1 − a) · a⁸)
```

- 풀이: "n번 연속 성공"이 처음 나올 때까지의 시행 횟수 기댓값 공식. 한 번이라도 틀리면 처음부터 다시 하므로 a가 조금만 낮아도 기댓값이 빠르게 커짐

| 정확도 a | E[루프 수] | 루프당 약 18초일 때 |
|---|---|---|
| 0.80 | 24.8 | 약 7.4분 |
| 0.85 | 17.8 | 약 5.3분 |
| 0.90 | 13.2 | 약 4.0분 |
| 0.95 | 10.1 | 약 3.0분 |

- 루프당 18초 = 운행 6초 + 문 열림·관찰 약 10초 + 버튼과 문 닫힘 약 2초 (추정)
- 목표 플레이 시간 5~10분이면 평균 정확도 0.8~0.85 근처가 적당. 이상현상 난이도를 이 값에 맞춰 조정

## 7. 연출

### 7.1 운행

- 실제로 엘리베이터를 움직이지 않음. 문이 닫혀 있는 동안 로비를 바꿔 끼우고, 아래 연출로 이동을 표현
  - 출발·정지 순간 카메라가 살짝 가라앉거나 떠오름
  - 모터 소리 (WebAudio 합성, 운행 중 음높이 변화)
  - 층 표시판 숫자 변화와 화살표
- 도착음 "딩" 한 번, 문 열림

### 7.2 추락 (오답)

1. 조명이 꺼지고 비상등(붉은빛)만 남음
2. 케이블 끊기는 금속음, 화면 강한 흔들림, 층 표시판 숫자가 빠르게 내려감
3. 충돌음과 함께 화면 암전
4. B8에서 문이 열리며, 놓친 이상현상 이름을 짧게 알려 줌 (끝없는 통로와 같은 방식)

### 7.3 놀래키는 장면 (최대 2종)

- 관리인이 엘리베이터 안에 있음 (#23): 문이 열리면 바로 옆에 서 있다가, 5초 안에 ▼를 누르지 않으면 고개를 돌려 다가옴 → 추락
- 거울 속 뒤에 서 있는 사람 (#12): 거울을 보는 순간 짧은 효과음

## 8. 조작

| 동작 | PC | 터치 |

- 엘리베이터 안이 좁아서 이동 속도는 끝없는 통로보다 느리게 (약 1.6m/s)

## 10. 플레이테스트에서 볼 지표

- 이상현상별 발견률 = 맞게 ▼를 누른 횟수 / 등장 횟수
  - 20% 미만: 너무 안 보임 → 크기·대비를 키우거나 쉬운 단서 추가
  - 95% 초과: 너무 쉬움 → 난이도를 낮게 재분류하거나 미묘하게 수정
- 오탐률 = 정상 루프에서 ▼를 누른 비율. 높으면 정상 상태에 "이상해 보이는" 소품이 있다는 뜻
- 시간 초과 비율 (보통 모드). 높으면 12초가 너무 짧음
